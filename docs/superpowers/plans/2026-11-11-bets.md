# Bets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fake-coin betting game: daily markets on other players' matches, free monthly futures picks that mint coins, a `/bets` page, and a betting rating on Home.

**Architecture:** Everything that decides money is pure and lives in `src/lib/domain/bets/`: pricing (Poisson + Elo), a deterministic per-Kyiv-day market generator, settlement, wallets, futures odds/payouts. The database stores only immutable facts: bets (with a copy of their spec and odds), futures odds snapshots and picks. Balances and settlements are recomputed on read from bets + matches, so match edits/deletes re-settle bets for free (same idea as `replayElo`). A thin server layer (`src/lib/bets/`) validates and inserts under a per-user advisory lock.

**Tech Stack:** Next.js 16 App Router (read `node_modules/next/dist/docs/` before touching app code), React 19, Drizzle ORM + drizzle-kit, Postgres, zod 4, vitest, Tailwind 4 + shadcn (base-ui), lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-11-bets-design.md` · Mockup: `docs/superpowers/mockups/2026-11-11-bets.html`

## Global Constraints

- `START_COINS = 1000`, `MARGIN = 0.05`, `FUTURES_BASE = 20`, `BET_DELAY_MS = 10 * 60_000`, `BET_TTL_MS = 7 * 24 * 3_600_000`, `PAIR_WINDOW_DAYS = 30`, `GROUP_HISTORY_DAYS = 60`, `MIN_PROB = 0.01`, `MAX_DAILY_ODDS = 50`, `MAX_FUTURES_ODDS = 100`, `BIG_WIN = 8`, `HIGH_SCORE = 15` — all in `src/lib/domain/bets/rules.ts`, nowhere else.
- All day/month boundaries are Europe/Kyiv (`src/lib/domain/time.ts`).
- Odds display: `×1.70` (2 decimals; 1 decimal at ≥10, e.g. `×15.0`) via one `formatOdds` helper. Never "@". Never a coin emoji; coin amounts are plain integers with `toLocaleString("en-US")`.
- Coin math is integer: returns `Math.round(stake * odds)`, futures payout `Math.round(FUTURES_BASE * odds)`.
- A user may never bet on a pair market they play in; group markets and futures (including picking yourself) are open to everyone.
- Minimal monochrome UI, matching existing components (`rounded-xl border`, `text-muted-foreground`, `font-mono tabular`); win/loss colours only via `text-win` / `text-loss`. No new npm dependencies (the shadcn dialog file uses the existing `@base-ui/react`). npm only.

## Review Focus

1. **A deciding match is edited or deleted after the bet settled** → the bet re-settles (won→lost, or back to open/refunded) and the balance follows; a balance pushed below zero blocks new bets with "Not enough coins." (Task 2 ledger test + Task 3 `checkBet` test.)
2. **The pair's match is logged with sides reversed** (B as `playerA`) → settlement compares user ids, not positions (Task 2 test).
3. **Two bets submitted in parallel that together exceed the balance** → only one is accepted (Task 5 DB integration test).
4. **Stale bet slip**: page opened before Kyiv midnight and submitted after, or odds moved because a match from earlier today was edited → rejected with a message naming the new odds / asking to refresh (Task 3 `checkBet` tests).
5. **Group bet placed at 23:55 Kyiv** → its window (from +10 min until midnight) is empty → refunded, not counted as a "No" win (Task 2 test); and a DST day (29 Mar 2026 has 23 hours) still ends at the right instant (Task 1 test).

**Interfaces:**
- Produces (`types.ts`):
  ```ts
  export type Side = "over" | "under";
  export type GroupCond = "bigWin" | "highScore" | "draw" | "playerWin";
  export type BetSpec =
    | { type: "winner"; a: string; b: string; pick: string /* userId | "draw" */ }
    | { type: "total"; a: string; b: string; line: number; side: Side }
    | { type: "margin"; a: string; b: string; winner: string; min: number; max: number | null }
    | { type: "score"; a: string; b: string; goalsA: number; goalsB: number } // goals of spec.a / spec.b
    | { type: "playerGoals"; a: string; b: string; player: string; line: number; side: Side }
    | { type: "streak3"; a: string; b: string; player: string }
    | { type: "group"; cond: GroupCond; player?: string; side: "yes" | "no" };
  export type BetStatus = "open" | "won" | "lost" | "void";
  export type Settlement = { status: BetStatus; matchIds: string[]; at: Date | null };
  export type BetRecord = { id: string; userId: string; spec: BetSpec; odds: number; stake: number; placedAt: Date;
    label: string; marketTitle: string; scope: string };
  export type FuturesPayout = { userId: string; month: string; amount: number }; // month = the predicted month
  export type Wallet = { userId: string; balance: number; atStake: number; openCount: number;
    won: number; settled: number; monthNet: number };
  ```
- Produces (`settle.ts`):
  - `settleBet(bet: Pick<BetRecord, "spec" | "placedAt">, matches: MatchRow[], now: Date): Settlement` — `matches` in replay order (`sortMatches`).
  - `betReturn(bet: Pick<BetRecord, "stake" | "odds">, status: BetStatus): number` — won → `Math.round(stake * odds)`, void → `stake`, else 0.
  - `isParticipant(spec: BetSpec, userId: string): boolean` — true for non-group specs where `userId` is `a` or `b`.
- Produces (`ledger.ts`): `wallets(userIds: string[], bets: BetRecord[], payouts: FuturesPayout[], matches: MatchRow[], now: Date): Map<string, Wallet>`
  - `balance = START_COINS + Σ payouts − Σ stakes + Σ betReturn`.
  - `atStake`/`openCount` over open bets; `won`/`settled` count won and (won+lost) bets all-time.
  - `monthNet` for `currentMonthKey(now)`: Σ (return − stake) of non-open bets whose `placedAt` is in that month + Σ payouts with `shiftMonth(p.month, 1) === currentMonthKey(now)` (a month's picks pay out when the next month starts).

Settlement rules (encode exactly):
- Window start `s = placedAt + BET_DELAY_MS`.
- Pair specs: candidate matches are those between `a` and `b` in either side order with `s ≤ playedAt < placedAt + BET_TTL_MS`. A user's goals = `m.playerAId === u ? m.goalsA : m.goalsB`.
  - `winner`/`total`/`margin`/`score`/`playerGoals`: decided by the first candidate; `total`/`playerGoals` lines are x.5, so there is no push. `margin` wins iff `winner` won by `d` with `min ≤ d ≤ (max ?? ∞)`.
  - `streak3`: walk candidates; first non-win by `player` → lost; third win → won.
  - No decision and `now ≥ placedAt + BET_TTL_MS` → `void`, `at = placedAt + BET_TTL_MS`; otherwise `open`.
- Group specs: window `[s, nextDayStart(dayKey(placedAt)))`. If `s ≥ end` → `void` at `end`. Qualifying match: `bigWin` |gA−gB| ≥ `BIG_WIN`; `highScore` max(gA,gB) ≥ `HIGH_SCORE`; `draw` gA = gB; `playerWin` `player` played and won. `yes`: first qualifying match → won at its `playedAt`; else at `now ≥ end` → lost. `no`: qualifying match → lost; else at `now ≥ end` → won at `end`. Otherwise open.
- `matchIds` = the matches that decided it (one, or up to three for `streak3`), `at` = the deciding `playedAt`.

Generator rules (deterministic; use only matches with `playedAt < dayStart(day)`):
- **Pairs:** unordered pairs with ≥1 match in `[dayStart − PAIR_WINDOW_DAYS, dayStart)`, ordered by number of matches in that window desc, then pair key. Within a pair `a` = higher current Elo (tie: smaller user id). `key = "${a}:${b}"`; `recent` = wins of each side in that window.
- **Lambdas:** `T` = (sum of total goals of the pair's last ≤20 matches + 5 × global average total of the last ≤100 matches) / (n + 5); `{la, lb} = splitLambdas(T, handicappedExpected(eloA, eloB))` (stars default → no handicap).
- **Markets per pair** (titles exact; usernames substituted; selection keys `${pairKey}:${marketSlug}:${n}`; omit selections whose `priceOdds` is `null`, omit empty markets):
  1. `Winner` cols 3 — `{A}` / `Draw` / `{B}`
  2. `Total goals` cols 2 — `Under {L}` / `Over {L}`, `L = floor(la + lb) + 0.5`
  3. `Correct score` cols 4 — the 4 most likely `(i, j)` from the grid, label `"{i}–{j}"` (A's goals first)
  4. `Winning margin` cols 3 — `{A} 1–2`, `{A} 3–5`, `{A} 6+`, `{B} 1–2`, `{B} 3–5`, `{B} 6+`
  5. `{A} goals` / `{B} goals` cols 2 — `Under {l}` / `Over {l}`, `l = floor(λ) + 0.5`
  6. `Specials` cols 1 — `{A} wins the next 3 in a row` (p = P(A wins)³), same for B
- **Group markets** (cols 2, `Yes`/`No`, scope `"Everyone"`): `A match is won by 8+` (bigWin), `Someone scores 15+ in a match` (highScore), `A match ends in a draw` (draw), `{X} wins a match` (playerWin; X = lowest-Elo user with a match in the last `PAIR_WINDOW_DAYS`, only when ≥3 such users). p = (k + 1) / (n + 2) over the play-days (Kyiv days with ≥1 match) in the last `GROUP_HISTORY_DAYS`, k = play-days where the condition held. No play-days → `group: []`.
- `findSelection` scope: `"{A} vs {B}"` for pairs, `"Everyone"` for group.

`checkBet` messages (exact, checked in this order):
1. `input.day !== ctx.today` → `"These odds are from yesterday. Refresh and try again."`
2. selection not found → `"This bet is no longer available."`
3. `isParticipant` → `"You can't bet on a match you play in."`
4. `selection.odds !== input.odds` → `` `The odds changed to ${formatOdds(selection.odds)}. Check and try again.` ``
5. `!Number.isInteger(stake) || stake < 1` → `"Enter a whole number of coins."`
6. `stake > ctx.balance` → `"Not enough coins."` (a negative balance always fails here)

### Task 4: Futures odds, pick window and payouts

**Files:**
- Create: `src/lib/domain/bets/futures.ts`
- Test: `tests/domain/bets/futures.test.ts`

**Interfaces:**
- Consumes: `monthStats` (`month.ts`), `computeAwards`, `awardValue`, `AWARDS` (`awards.ts`), `fairOdds`, `FUTURES_BASE`, `shiftMonth`, `currentMonthKey`.
- Produces:
  ```ts
  export type FuturesKey = AwardKey | "potm";
  export const FUTURES_QUESTIONS: { key: FuturesKey; label: string; emoji: string; sub?: string }[]; // potm first ("Player of the Month", "👑"), then AWARDS in order; winRate has sub "5+ games"
  export type FuturesOdds = Partial<Record<FuturesKey, Record<string, number>>>; // userId → odds
  export type FuturesPick = { userId: string; question: FuturesKey; pickUserId: string };
  export function futuresOdds(target: string, matches: RatedMatch[], userIds: string[]): FuturesOdds | null;
  export function picksOpen(target: string, now: Date): boolean; // currentMonthKey(now) === shiftMonth(target, -1)
  export function futuresPayouts(target: string, odds: FuturesOdds, picks: FuturesPick[], result: Pick<MonthAwards, "awards" | "playerOfMonth">): FuturesPayout[];
  ```

Odds algorithm (encode exactly): source months `shiftMonth(target, -2)`, `-3`, `-4` with weights `1, 0.5, 0.25`. Participants = users with ≥1 game across those months; fewer than 2 → `null`. Per question and participant: `s = Σ weight × v`, where `v = max(0, awardValue(stats, key))` for awards (0 for `winRate` when `games < 5`) and `v` = awards won that month (from `computeAwards`) for `potm`. `p ∝ s²`; if all `s = 0` → uniform; then `p = max(p, MIN_PROB)` and renormalise; odds = `fairOdds(p)`.

Payouts: for each pick whose `pickUserId` equals the winner (`result.awards[key]?.userId`, or `result.playerOfMonth?.userId` for `potm`) → `{ userId, month: target, amount: Math.round(FUTURES_BASE * odds[key][pickUserId]) }`. No winner or no odds for that player → nothing.
